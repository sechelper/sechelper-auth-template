# ADR 0002：管理后台菜单配置与框架边界

## 状态

已采用。

## 背景

管理后台需要允许业务模块调整自身分组顺序、增加和删除业务菜单，而不要求修改框架布局。当前路径展示、菜单层级和折叠行为也应由同一份导航声明驱动，避免页面重复配置。

## 决策

- 管理后台菜单由框架固定菜单和自动发现的业务模块导航声明合并。
- `概览`、`账号与安全`、`监控与审计`及其页面和路由由框架拥有。业务模块不得声明这些分组或框架路由。
- 业务导航项使用 `section` 指定分组，使用可选数值 `sectionOrder` 排列分组；数值越小越靠前，未指定时业务分组排在固定框架分组之后。未分组的框架入口始终在分组之前。
- 固定框架分组采用框架指定顺序，业务分组不能改变它们之间的相对顺序。同名业务分组必须声明一致的 `sectionOrder` 和 `sectionCollapsible`。
- 框架根据当前路由递归匹配合并后的菜单，统一显示当前菜单路径并展开当前页面的分组与父级节点。路径不包含同级分组标题。
- 导航项仍须与业务路由一一对应并声明相同权限。框架校验声明，前端限制导航和直接访问，服务端负责最终授权。

## 影响

调整业务分组位置只需修改对应 `admin-module.js` 的 `sectionOrder`。增加或删除业务菜单只需修改对应业务模块声明，不需要改后台布局、框架菜单顺序或当前路径组件。账号安全和监控审计等框架导航不受业务模块生命周期影响。

## 回滚

移除 `sectionOrder` 的排序解析和校验，并恢复固定位置合并逻辑。业务声明中的 `section`、路由和权限仍可保留。
