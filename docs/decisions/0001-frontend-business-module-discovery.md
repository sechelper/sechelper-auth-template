# ADR 0001：前端业务模块自描述与自动发现

## 状态

已采用。

## 背景

业务页面位于可写业务目录，但原有前后台注册器需要逐个手工导入模块。每新增一个菜单或路由都会触及只读框架文件，使普通业务交付依赖框架维护授权。`orders` 仅用于演示边界，不代表真实业务需求。

## 决策

- 业务前台模块在 `web/src/business/<module>/public-module.js` 默认导出模块声明。
- 管理后台模块在 `web/admin/src/business/<module>/admin-module.js` 默认导出模块声明。
- Vite 在构建期通过固定的单层 `import.meta.glob` 模式发现声明，框架不保存逐模块导入清单。
- 管理后台声明的每条路由和导航必须包含权限码；框架同时保护导航可见性和直达路由，服务端继续负责权威授权。
- 重复模块名、重复路由、重复导航、越界路径、缺少组件或权限均导致前端初始化失败。
- 模块发现按声明文件路径排序，导航再按 `order` 数值排序，保证构建结果稳定。
- `enabled: false` 可保留不进入默认应用的演示声明；真实业务模块默认省略该字段。

## 影响

新增或删除普通业务模块只改变对应的业务目录，不再修改主入口、全局路由或框架注册器。改变描述字段、发现范围或校验规则仍属于框架维护任务。自动发现发生在构建期，不允许从远端或运行时加载未审查代码。

## 回滚

恢复前后台注册器的显式模块数组，并删除业务模块描述文件。业务页面实现不需要随之删除，但在显式登记前不会进入应用。
