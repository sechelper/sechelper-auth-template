# 后台“开发参考”模块清理快捷文档

## 目的

新业务接入前，清除后台管理中的“开发参考”测试模块，避免组件示例、虚构数据、参考页面和测试路由进入正式项目。

本文档本身属于清理指南，必须保留，不属于待清理的“开发参考”业务内容。

## 清理范围

重点检查并清除以下内容：

- `web/admin/src/business/component-reference/**`
- `component-reference` 模块声明、动态发现引用和模块注册引用
- `/admin/component-reference` 路由及其页面组件
- “开发参考”菜单分组、组件参考菜单项及相关权限声明
- 组件参考页面中的虚构姓名、编号、状态、金额、表单和调试数据
- 构建、部署、测试配置中仅用于该模块的检查、白名单或示例引用

## 快速执行顺序

1. 全量检索 `component-reference`、`/admin/component-reference`、`开发参考`、`组件参考` 及相关模块文件名。
2. 确认目标内容属于后台测试/示例模块，不是正式业务页面，也没有被当前业务依赖。
3. 删除组件参考页面、样式、模块声明和该模块专属的路由、菜单、权限及构建引用。
4. 不得修改后台框架入口、全局路由、Provider 或通用模块发现机制来规避清理检查。
5. 再次全量检索，确认没有“开发参考”模块、组件参考页面和测试路由残留。
6. 复核完整 Git 差异，并执行 `make architecture-check` 及本次业务相关验证。

## 验收标准

- 不存在 `web/admin/src/business/component-reference/` 目录。
- 不存在 `/admin/component-reference` 路由、`component-reference` 模块声明和“开发参考”菜单。
- 不存在仅属于该模块的虚构数据、示例组件、调试逻辑和测试配置。
- 正式构建和部署内容不再引用该测试模块。
- 没有修改后台框架入口、全局路由或通用模块发现机制。

## 风险提示

不得按“reference”或“order”字符串直接批量删除文件。`reference` 可能出现在通用文档或代码注释中，`order` 可能表示通用排序字段；必须结合模块路径、路由和业务用途逐项确认。
