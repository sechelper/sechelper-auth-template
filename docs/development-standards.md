# 开发规范

## 前端视觉与交互

当前需求、产品设计和品牌要求优先；没有额外设计要求时，沿用 `web/` 与 `web/admin/` 现有实现中的样式令牌、组件、布局和交互约定。仅调整需求涉及的页面或组件，不因新增功能而顺带重做无关页面。

- 在对应前端的样式入口复用已有颜色、间距、圆角、阴影和状态令牌，避免在组件内复制出近似但不一致的值。
- 页面应有清楚的信息层级和主要操作；避免互相竞争的多个主操作、过度装饰和损害可读性的效果。
- 覆盖适用的加载、空、错误、未授权、重试和操作进行中状态。状态不能只依赖颜色，还应提供文字、图标、形状或可访问标签。
- 保留 `SECHELPER COMMUNITY` 品牌呈现、Logo 原始比例和项目既有认证边界。视觉实现不得改变认证、授权、接口或数据规则。
- 按产品需求支持目标屏幕尺寸，并保持现有断点与导航行为一致；不得自行扩大改造范围。
- 遵守 WCAG AA 的可访问性目标，为键盘操作提供清晰焦点样式，避免缩放或长文本导致内容重叠；对比度不足时以可读性为准调整。
- 业务逻辑放在对应业务模块和 Go API 中，不写入样式或纯展示组件。

## 交付检查

视觉变更应检查品牌呈现、信息层级、键盘焦点、状态反馈、目标视口和文本缩放；说明变更覆盖范围，并验证未改变认证、权限和 API 行为。
